## 这次原型要回答的问题

1. 已确认的复杂规则能否在同一确定性结算核心中无歧义运行？
2. 普通视野、车路径视野、隐身马、相象显形、炮架与随机结果是否能通过 `PlayerView` 保持无泄露？
3. 同一初始状态、种子和行动序列能否稳定得到相同状态与事件摘要？
4. 单机 AI 是否能在只读取玩家等价可见信息时完成合法对局，并留下可审计证据？
5. 这些系统是否共同形成值得进入正式开发的移动—侦察—破城—争旗—终局闭环？

## 通过标准摘要

- Godot 4.7.1 无错误导入，预置原型场景可无头加载。
- 规则矩阵、结算优先级、确定性回放、隐藏等价配对和 AI 公平性必要测试全部通过。
- 至少 1000 个固定种子完整对局合法终止，无崩溃、非法行动或不可复现分歧，并形成轮数、胜因、先后手和旗帜分布统计。
- QA 使用与生产岗位不同的 Agent Instance 独立验收，不能由规则、技术或 AI 生产者自证。
- 项目所有者基于可运行原型、试玩记录、风险与技术成本作出 `GATE-1` 决定。

## 明确不做

- Contract 获批前不创建 Godot 工程。
- GATE-1 前不生产正式美术、音频、动画、正式 UI 或量产资产。
- 不把可丢弃原型代码自动继承为正式架构。
- 不在证据形成前冻结单局轮数上限、AI 搜索预算、随机性或难度档位。
- 不引入在线联机、排位、专用服务器或机器学习。

## 需要项目所有者批准的决定

请批准或要求修订以下绑定内容：

1. 首个循环范围是否只覆盖规则核心、迷雾、确定性与 AI 公平性，不包含正式资产生产；
2. 是否接受最多 3 轮修订，耗尽后暂停复审；
3. 是否接受“1000 个固定种子完整对局 + 隐藏等价配对测试 + 独立 QA”作为客观准入基线；
4. 是否允许 Contract 获批后创建 Godot 4.7.1 工程和可丢弃逻辑原型；
5. 是否确认只有通过 `GATE-1` 后，才能进入正式功能开发与资产生产。

批准动作本身不是 `GATE-1`。它只允许启动原型生产循环；`GATE-1` 必须等原型和独立证据完成后另行判断。
