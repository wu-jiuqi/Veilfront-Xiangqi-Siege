# “兵马俑”专属美术管线 v1

状态：`owner_named / preproduction_ready / batch_production_pending_gate2`

管线 ID：`terracotta-warriors`

适用范围：仅适用于选择“兵马俑”风格的棋盘、棋子、结构、UI、特效和配套音频表现。

全局技术基线：`docs/art/veilfront-visual-baseline-v1.md`

机器可读清单：`docs/art/pipelines/terracotta-warriors/asset-inventory-v1.yaml`

## 1. 固定结论与边界

“兵马俑”是《雾疆》的一套可选命名美术管线，不是项目全局美术风格。以后新增美术风格时，应建立新的同级管线目录，不得覆盖本管线，也不得把本管线的材质、字体、纹样或 UI 规则提升为全局规则。

本管线固定以下规则：

- 角色采用金属兵马俑语言：秦俑式体态、层叠札甲、无裸露皮肤、全身金属化。
- 所有角色面部使用没有眼孔、鼻、嘴和表情浮雕的光滑曲面面具。
- 黑方主材质为深墨绿青铜：整体压至近黑绿，少量铜绿只出现在凹面，轮廓边缘使用清晰但克制的青铜磨边高光。
- 红方主材质为高明度银白钨钢：冷银白金属面、浅中灰钢底、蓝灰反射和清晰冷色镜面高光；不得变成镜面铬，暗朱系绳只能作小面积辅助。
- 金色只用于目标、军令、关键纹章和七兵种的职位字，不能大面积覆盖甲胄。
- 每个兵种以合乎装备用途、不突兀的位置承载一个金色职位字：`兵/炮/车/马/相/士/将`。概念页必须准确可读且不得出现伪字；正式资产必须使用经过文字校对和授权确认的秦小篆风格矢量字形，生成图中的字形不能直接拆出作为生产母版。
- 红黑两方除材质外，还要通过冠形、肩甲、盾缘、护胫和主道具轮廓区分。红方优先方正冠形、方肩与锐利边缘；黑方优先弯钩冠形、圆弧叠甲与厚重铜边。
- 金属质感必须依靠镜面高光、粗糙度层次、边缘磨损和冷暖环境反射成立；禁止画成陶土、石像、塑料或大面积布甲。

项目所有者提供的甲士图只作为层叠札甲、宽肩重盾、克制纹样和金属重量感参考，不复制原图的具体纹样、文字或完整造型。生成式概念图只用于方向审查，不可直接作为最终透明立绘、字体或商用纹样。

## 2. 总量口径

本管线的棋子角色母版总数为 **14个**：

```text
（兵 + 炮 + 车 + 马 + 相 + 士 + 将）×（红方 + 黑方）= 14
```

同阵营同兵种在棋局中出现多个实例时复用同一角色母版，不重复计算新的角色设计。皮肤、升阶、受损差分和节庆变体不在 v1 数量内，必须另立变体清单。

## 3. 棋盘制作方案

棋盘采用“秦军军阵沙盘”而非传统平面象棋盘。技术结构继续服从全局基线的 24×9 一基交点与斜俯视 Node3D 方案。

### 3.1 预置场景结构

```text
TerracottaBoard3D (Node3D)
├─ BoardBase (MeshInstance3D)
├─ GroundMaterialLayer (MeshInstance3D)
├─ GridOverlay (MeshInstance3D)
├─ ZoneOverlay (MeshInstance3D)
├─ FogSurface (MeshInstance3D)
├─ WallRoot (Node3D)
├─ PropRoot (Node3D)
├─ FlagRoot (Node3D)
└─ HighlightRoot (MultiMeshInstance3D)
```

固定节点、Mesh、Material、Theme 和默认资源引用必须在 `.tscn/.tres` 中预置。只有由对局数量和 PlayerView 决定的棋子实例、旗帜状态和可见事件允许动态实例化。

### 3.2 制作步骤

1. 在 Blender 制作约 `11.4 × 0.22 × 29.4` 世界单位的薄实体底板，四边做黑化青铜包边和克制秦式几何纹，输出 `.blend + .glb`。
2. 使用 SVG 或无损绘图工具制作精确 9路×24线网格；按 216 个逻辑交点校验后输出透明贴图。生成式图片不得参与线条生成。
3. 以可平铺 PBR 地表表现压实黑土、风沙与军阵踩踏痕；网格、地表、区域色和装饰贴花保持独立材质层。
4. 大本营、缓冲区和战区通过轻微色相、粗糙度和不越界的大字区分，不新增规则分割线。
5. Y=4 与 Y=21 的城墙制作成独立预置结构，提供完整、受损、倒塌、修复中四种状态；不得烘进棋盘底图。
6. 棋盘边界布置兵器架、军鼓、烽火盆、残车、箭簇、军帐桩等模块；装饰不能占用交点或暗示隐藏规则。
7. 使用单一 9×24 迷雾 mask 和独立 FogSurface，不为216个格点创建节点，不创建未授权敌方表现。
8. 在 `960×540 / 1280×720 / 1920×1080` 和红黑双方视角下验证网格、遮挡、材质、点击与 UI 安全区。

Godot 实现优先建立独立 `Theme.tres`，由现有 Control/Container 场景引用；不要为该皮肤复制业务逻辑或用脚本动态生成整套 UI。

## 9. 文件与导入规范

建议正式目录：

```text
assets/art/pipelines/terracotta_warriors/
├─ board/
├─ pieces/red/
├─ pieces/black/
├─ structures/
├─ fog/
├─ flags/
├─ ui/
├─ fx/

└─ materials/

scenes/presentation/styles/terracotta_warriors/
├─ terracotta_board_3d.tscn
├─ pieces/
└─ terracotta_ui_theme.tres
```

- 直立角色源图：`1024×1536` 透明 PSD/PNG；运行时最大 `512×768`。
- 宽体角色源图：`1536×1536` 透明 PSD/PNG；运行时最大 `768×768`。
- 角色透明边缘保留 8～16px 安全边距和透明像素扩色，统一脚底线与构图中心。
- 棋盘和结构：保留 Blender 源文件，运行时使用 GLB；静态模块提供 LOD，碰撞网格按 Godot 命名约定输出。
- 3D表面纹理开启 mipmap 和 VRAM Compression；UI 纹理不启用 mipmap；图标保留 SVG 源。
- 源文件、导出文件、授权记录和 Godot 导入资源分开保存，不把生成式概念图当成最终可发行资产。

## 11. 最终验收

- 14个棋子在 1280×720、普通棋子高度约96～180px时可凭轮廓和主道具识别。
- 红黑双方在灰度和常见色觉弱化模拟下仍能区分；材质差异不依赖SSR或高级后处理。
- 前后排不连续遮住两个以上交点，透明排序、脚底线和假阴影稳定。
- 棋盘216个交点与一基坐标逐点一致；装饰、城墙和UI不阻塞点击。
- 迷雾、特效、音效、小地图和动画不泄露 PlayerView 之外的信息。
- UI 三分辨率无裁切，主要按钮、焦点、错误、危险与当前回合状态清晰。
- 每项资产具备源文件、导出物、许可证/来源、负责人、版本、验收截图和 Godot 导入记录。
