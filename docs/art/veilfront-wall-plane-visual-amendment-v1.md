# 《雾疆：九路烽棋》城墙平面化视觉修订 v1

状态：`owner_direction_confirmed / applies_to_TASK-ART-001 / pending_independent_QA`

确认日期：`2026-08-20`

来源：`codex-thread://current#owner-confirm-wall-on-board-plane`

## 1. 决定

红墙 `Y=4` 与黑墙 `Y=21` 不再制作成高于棋盘、阻挡轮廓的实体三维墙。正式表现改为贴合棋盘表面的“城防阵线”：用纹理、材质、符印和状态特效表达规则状态，棋子仍严格落在同一权威交点线上。

本修订保留斜俯视 Node3D 棋盘、Sprite3D 棋子、低FOV摄像机、PlayerView信息边界和一基坐标，不改玩法、行动合法性、墙状态机、随机消费、回放或教学语义。

## 2. 对v1基线的取代范围

本文件只取代以下城墙表现条款，不覆盖 `docs/art/veilfront-visual-baseline-v1.md` 的其他内容：

- “Y=4/Y=21城墙必须作为有高度的独立三维结构物”改为“独立的贴地表现层/预置场景”。
- 棋盘底图仍不得烘入城墙；城墙状态必须能独立切换。
- “结构模型GLB”改为透明纹理＋PlaneMesh/Decal/等价贴地材质资源。
- 城墙状态从美术清单旧四态收敛为规则三态：`INTACT / BREACHED / REPAIRING`；“受损”只是一过性反馈。

“城墙不是区域分割线”的语义继续成立：城防阵线只标记规则墙线，不新增区域边界或可通行缺口。

## 3. 视觉语义

| 规则状态 | 平面表现 | 禁止误读 |
|---|---|---|
| `INTACT` | 连续双层金属嵌线、九路节点和稳定阵营符印 | 不显示生命值、入侵数量或隐藏计时 |
| `BREACHED` | 全线均匀断裂、符印熄灭、碎片与焦痕分散 | 不只打开单个缺口，不暗示限定通路 |
| `REPAIRING` | 仍保持断裂，在全线叠加循环重组能量 | 不显示百分比，不提前看成完整墙 |
| 受损反馈 | 短暂震荡、裂纹闪光、碎屑或能量波 | 不形成第四种持久状态 |

棋子、选择环、合法落点、路径和确认反馈始终位于城墙层上方。贴地资源没有碰撞体，不参与输入射线或规则判定。

## 4. Godot预置约束

首轮样片使用预置场景：

```text
WallPlane3D (Node3D)
├─ Intact (MeshInstance3D)
├─ Breached (MeshInstance3D)
└─ Repairing (MeshInstance3D)
```

三个状态节点均预置，只由观察者安全的 `PlayerView.walls[].status` 切换可见性。根节点锚定权威墙线，PlaneMesh离棋盘表面约 `0.018` 世界单位以避免Z-fighting；不得从节点可见性反推任何未公开修复进度。

## 5. 首轮范围与验收

首轮只制作红方三状态，黑方在红方样片通过后按同一状态语义制作阵营变体。必须验证：

- 五枚兵位于同一墙线上时没有穿模或轮廓遮挡；
- `960×540 / 1280×720 / 1920×1080` 和双方180°视角下三状态一眼可辨；
- 网格、墙线、棋子、选择/落点高亮没有Z-fighting或层级混淆；
- `REPAIRING` 仍能被理解为可通行状态；
- 墙状态只消费PlayerView公开字段，不泄露入侵数量或修复内部计时。

## 6. 治理影响

这是一项 `TASK-ART-001` 内的表现手段修订，不改变Contract v2范围、交付物、职责、预算或GATE-2问题，因此不升级Contract版本。v1基线和旧三维墙灰盒作为历史证据保留；本修订与墙资源增量清单共同作为后续制作输入。
