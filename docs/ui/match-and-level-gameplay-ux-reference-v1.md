# 联机对局与关卡闯关 HUD 布局参考 V1

日期：2026-08-23
状态：`concept_reference / pending_owner_review`
画布：`1672×941`，按 `1280×720` 安全区评审

## 范围纠正

本轮只优化两个运行时战局界面：

1. 联机双方已经开局后的正式对局 HUD。
2. 玩家进入关卡后的闯关／教学 HUD。

不包含联机房间大厅，也不包含关卡选择地图。两张参考图必须独立评审和实现，不得拼成一张运行时画面。

## 共同布局骨架

- 中央 `9×24` 棋盘占可用画布约 `66%–72%`，始终是第一视觉层。
- 顶部中间只承载当前阶段：联机版为回合／行动方／计时，闯关版为关卡名／步骤进度。
- 左上为小地图，左下为可折叠单位卡；未选中棋子时应折叠，避免空面板持续占据视觉重量。
- 右栏使用单一抽屉，不叠加第二块常驻提示窗。
- 底部按 `行动模式 → 上下文说明 → 确认／取消` 排列，确认按钮使用跨页面一致的 Primary 反馈。
- 正文目标为 `16 px`，次级信息不低于 `14 px`，操作控件高度不低于 `48 px`。

## 联机对局差异

- 右栏只显示当前观察者已获授权的公开战况与事件，最多五行。
- 对手回合不得显示对方选择、目标、预览、鼠标或私有标记。
- “确认行动”必须经过准备／确认／提交链；主动跳过仍需防误触确认。
- 当前模式、不可用模式、键盘焦点和提交锁必须具有不同且稳定的视觉状态。

参考图：`assets/art/ui/concepts/multiplayer_match_hud_ux_reference_v1.png`

## 关卡闯关差异

- 右栏固定为四段：关卡目标、步骤清单、当前操作、上下文提示。
- 玩家首先看到“现在做什么”，目标背景和可选提示处于次级层。
- 选中棋子、合法路径、目标交点和当前步骤必须互相回应，但不以大段文字覆盖棋盘。
- “显示提示”与“重置步骤”使用次级反馈；“确认移动”使用主确认反馈。

参考图：`assets/art/ui/concepts/level_challenge_hud_ux_reference_v1.png`

## 动效建议

- Hover：`140 ms`，轻微抬升或 `1.02` 缩放。
- Press：`80 ms`，缩放至 `0.96–0.97`。
- Focus：`160 ms`，连续金线和 `1.01` 级缩放，禁止用 Hover 冒充键盘焦点。
- 路径／目标点：`180 ms` 建立高亮；循环呼吸同屏最多一处。
- 开启减少动态效果后，关闭位移、缩放和循环呼吸，只保留颜色／透明度变化。

## 生产约束

- 优先使用预置 `Control / Container / Theme` 与共享 `UiMotionButton` 变体；仅由对局数据决定数量或生命周期的内容可运行时实例化。
- 概念图中的文字、棋盘、图标和棋子排列不得直接作为发行资源。
- 联机 HUD 必须继续通过 `PlayerView / VisibleEvent / ActionPreview` 白名单驱动，不得因布局改版扩大信息权限。
- 关卡 HUD 应复用正式 `MatchScreen` 骨架和右侧信息列，不建立与正式对局完全分叉的第二套交互系统。

使用内置 `image_gen`，两张图片分别生成：

- 联机对局：以当前正式战局截图和 `battle_hud_concept_v1.png` 为参考；单一 16:9 对局屏；棋盘占约七成；顶部回合条；左侧小地图／单位卡；右侧公开战况；底部五槽行动栏与确认链；禁止大厅、关卡地图和隐藏信息。
- 关卡闯关：以当前 T03 HUD、正式战局截图和 `level_gameplay_hud_concept_v1_t03_field_lattice.png` 为参考；单一 16:9 闯关屏；复用战局骨架；右栏重排为目标／步骤／当前操作／提示；演示红相、目标交点与路径高亮；禁止关卡选择地图和联机大厅控件。

两次生成均要求：暗铁、氧化青铜、克制旧金、暗朱／深玉阵营色；高对比中文信息；低装饰密度；可拆为 Godot 九宫格和预置控件；无水印、无伪品牌、无拼图式画布。
