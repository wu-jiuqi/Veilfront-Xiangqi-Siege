## 1. 目的与边界

本规格冻结 `UiMotionButton` 四类预置语义、按钮状态反馈、字体与颜色角色、焦点闭环和响应式验收标准，使 Godot 技术实现与 QA 可以依据同一组可执行事实工作。

本规格不新增按钮动作、页面、规则、信息、确认步骤或内容范围；`Confirm` 只是已有“提交/应用/开局”等确认动作的统一表现语义。是否允许行动、行动结果与可见原因必须来自当前玩家的 `PlayerView`、公开事件或公开设置状态，禁止 UI 为了反馈读取 `FullState`、隐藏目标、隐藏合法行动或规则 RNG。

状态标签保持如下：

- `confirmed`：本文件中的预置语义、状态行为、字号/颜色角色、点击高度、焦点规则和分辨率验收标准。
- `hypothesis`：具体 Godot 场景继承层级、Theme variation 继承关系、Tween/AnimationPlayer 分工、状态切换脚本和动态焦点改线方式；由技术负责人选择并验证，不得反向改变本规格语义。
- `unknown`：四类预置的最终纹理细节、光扫形状、描边装饰和最终审美签核；这些不阻塞基础实现，但不能标记为项目所有者已批准。

## 2. 共用基础

所有四类按钮必须使用同一 `UiMotionButton` 行为合同和共享 motion profile，不允许页面实例把共享 profile 覆盖为 `null`。场景以预置 `Control` / `Container` / `Theme` 资源为主；运行时脚本只负责状态驱动、公开数据绑定和确有必要的动态焦点修补。

按钮状态优先级固定为：

1. `disabled`：覆盖其他状态并立即停止旧动效；
2. `pressed`：保持可见焦点边线，不被 hover 覆盖；
3. `focus + hover`：同时保留键盘焦点边线和鼠标 hover 反馈；
4. `focus`；
5. `hover`；
6. `normal`。

鼠标经过不得抢夺键盘/手柄焦点。任何新状态开始前必须终止该控件仍在运行的旧 Tween，同一属性不能出现并发竞争。动效不能阻塞输入、延迟权威状态更新或改变控件实际布局矩形；缩放与位移只作用于视觉偏移。

## 3. 四类 `UiMotionButton` 预置

| 预置 | 使用语义 | 允许示例 | 不允许替代 | 默认视觉重点 |
|---|---|---|---|---|
| `Primary` | 当前页面的主要前进或进入动作，但不表示已经提交不可逆状态 | 联机对战、关卡模式、进入关卡、重试 | 危险操作、普通返回、已经准备好的棋局提交 | 主文字 + 强调金；同一操作组只保留一个主视觉中心 |
| `Secondary` | 可逆、导航、取消或低权重并列动作 | 返回、取消、关闭、普通页签辅助动作 | 确认行动、重置进度、开始游戏 | 主/次级文字 + 克制玄铁/青铜边框 |
| `Danger` | 已有流程中的破坏性、高损失或需谨慎动作 | 重置进度、已有确认流程保护的退出/放弃 | 普通取消、奖励性确认、无风险导航 | 铁红表面/边框；不得复用金色成功印记 |
| `Confirm` | 对玩家已经选择或编辑的内容进行明确提交 | 确认行动、应用设置、确认准备、开始游戏、下一章 | 尚未准备完成的入口动作、危险操作 | 强调金 + 确认印记；必须与 Primary 在语义上可区分 |

补充规则：

- 预置由动作语义决定，不能仅为“看起来更醒目”而升级为 `Primary`、`Danger` 或 `Confirm`。
- `Confirm` 在提交条件未满足时使用 `disabled`，不能用隐藏信息解释禁用原因。
- `Danger` 沿用对应流程既有的确认政策；本基础规格不自行增加或取消确认弹窗、长按或二次确认。
- 弹窗中的默认焦点必须落在安全的 `Secondary` 取消项，不得默认落在 `Danger` 或会立即提交的 `Confirm`。

## 4. 状态与动效合同

### 4.1 默认动态效果

| 状态 | 时长与曲线 | 几何反馈 | 色彩/边线反馈 | 验收要点 |
|---|---|---|---|---|
| `normal` | 状态落定 | 缩放 `1.0`、位移 `0` | 使用预置普通色 | 无残留 Tween 或偏移 |
| `hover` | `140 ms`，Cubic Out | `Secondary` / `Danger` 上移 `2 px`、缩放 `1.02`；`Primary` / `Confirm` 朝操作方向移动最多 `6 px`、缩放 `1.025` | 字色/边框提高明度，但不能淹没焦点线 | 鼠标进入可感知；离开后回到 focus 或 normal |
| `pressed` | `80 ms`，Cubic Out | 缩放 `0.965`，视觉压下最多 `1 px` | 明度相对当前态下降约 `12%` | 键盘焦点线仍可见；禁用时不可进入 |
| `release` | `120 ms`，Back Out | 回到当前 hover、focus 或 normal 的目标值 | 回到对应目标色 | 不等待该动画才发送原有动作 |
| `focus` | `160 ms`，Cubic Out | 缩放 `1.015`，不强制位移 | 连续、静止、完整的强调金焦点线 | 不能用 hover 外观代替；暗/亮背景均可辨认 |
| `disabled` | 立即切换 | 缩放 `1.0`、位移 `0` | 禁用色，纹理/边线降低对比；无呼吸或扫光 | 立即杀死旧 Tween；不接收焦点或激活 |

`Primary` / `Confirm` 的“操作方向”由版面阅读方向确定；没有明确方向时只上移 `2 px`。`Confirm` 可在动作已经由业务层接收后播放一次 `220 ms` 金色印记，`Danger` 只允许铁红收束/压暗，不得播放奖励式金色印记。附加反馈不能延迟场景切换或正式 Intent/Event。

### 4.2 减少动态效果

开启“减少动态效果”后：

- 禁止缩放、位移、抖动、扫光移动、弹性回弹和循环呼吸；
- hover、press 与 focus 只保留 `100 ms` 的颜色/透明度过渡，pressed 可保留不超过 `80 ms` 的压暗；
- focus 使用静止连续边线，disabled 立即落定；
- Confirm/Danger 的附加印记改为静态颜色或透明度切换；
- 开关切换时立刻停止旧 Tween 并复位几何状态，不能等当前动效结束。

减少动态只改变表现，不改变输入时机、可操作性、焦点顺序、提示内容或游戏结果。

## 5. 尺寸与点击区域

高度标准指布局后的真实可交互矩形，不计 hover/press 的视觉变换：

| 场景档 | `Secondary` / `Danger` | `Primary` / `Confirm` | 说明 |
|---|---:|---:|---|
| 1280×720 基准及 1920×1080 | 至少 `48 px` | 至少 `56 px`，高价值主按钮可保持现有 `64 px` | 常规生产基线 |
| 960×540 紧凑布局 | 绝对下限 `44 px` | 至少 `48 px` | 只允许压缩间距和次要装饰，不压缩文字至角色下限以下 |

按钮宽度必须容纳完整核心动作文本及左右内边距。核心动作文本不得依赖截断号表达；本地化后空间不足时优先换用容器重排、允许的短文案或页面滚动，不能通过整体缩放 UI 规避。

## 6. 字体与字号角色

| 角色 | 字体 | 1280×720 基准 | 使用范围 | 约束 |
|---|---|---:|---|---|
| `Display` | ramega 张青平行书 | `28–44 px` | 页面标题、章节名、阵营气氛字 | 不用于按钮、正文、数值或操作性小字；任何档位不得低于 `26 px` |
| `Heading` | Noto Sans SC 600 | `20–28 px` | 面板、关卡、结果标题 | 层级由字号/字重建立，不靠低对比色 |
| `Body` | Noto Sans SC 450–500 | `16 px`，行高 `24 px` | 教学正文、任务描述、设置标签、核心说明 | 960×540 不得继续缩小；正式战局核心正文不得低于 `15 px` |
| `Secondary` | Noto Sans SC 450 | `14 px`，行高 `20 px` | 快捷键、补充提示、次级状态 | 不得独自承载核心规则、行动结果或失败原因 |
| `Control` | Noto Sans SC 550–600 | `16–20 px` | 按钮、页签、选项框 | 四类按钮必须使用；960×540 不得低于 `16 px` |
| `Numeric` | Noto Sans SC 500 | `16–28 px` | 回合、比分、百分比、房间号 | 使用等宽数字能力；不可因数字变化引发布局跳动 |

1920×1080 与 21:9 可以增加留白和内容容器空间，但不能无上限等比放大文字或边框。教学正文固定以 Body 为最低角色，不能退化为 Secondary。

## 7. 颜色角色与可读性

| 角色 | 色值 | 用途 |
|---|---|---|
| `TextPrimary` | `#E8DEC5` | 正文、按钮与关键状态 |
| `AccentGold` | `#E8BC62` | 焦点、确认、当前重点；不能铺满所有可点击项 |
| `TextSecondary` | `#AFA58F` | 非关键补充信息 |
| `TextDisabled` | `#6E6A61` | 明确不可用状态；不能作为正文色 |

铁红是 `Danger` 的表面/边框语义，不替代以上四级文字角色。纹理背景上的 Body、Control 与 Numeric 文本必须使用 `1–2 px` 深色描边或独立半透明衬底，避免直接叠在高纹理区域。实现验收目标为普通正文/控件文字对背景至少 `4.5:1`，大号 Display/Heading 与焦点边界至少 `3:1`；若现有贴图不满足，优先增加衬底或描边，不静默改变正式主色方向。

状态不能只依赖颜色区分：focus 必须有连续边线，disabled 必须同时具有低对比外观与不可交互状态，Danger 必须有形状/边框语义，Confirm 必须有确认印记或等价非色彩标记。

## 8. 显式闭环焦点规则

### 8.1 全局规则

1. 所有当前可见且可操作的 Button、TextureButton、CheckButton、OptionButton、Slider、LineEdit、页签和棋盘外围操作控件必须可由键盘/手柄获得焦点；纯装饰节点不能进入焦点链。
2. 每个主要页面和每个模态弹窗都必须显式定义 Next/Previous 闭环；上下或左右排列的操作组还必须显式定义对应方向邻居。不得以 Godot 几何推断作为正式导航路径。
3. 从任一可操作控件连续执行 Next 或 Previous，必须在有限步内回到起点，且途中不能进入隐藏、禁用、屏外或被遮挡控件。
4. 单控件操作组的闭环指向自身；模态弹窗打开时焦点被限制在弹窗内，关闭后返回打开弹窗的控件。
5. 当前焦点控件变为隐藏或禁用时，焦点转移到同组最近的安全可用动作；找不到时转移到页面既定安全入口，不得落到 Danger 或立即提交的 Confirm。
6. 页面首次进入默认聚焦阅读顺序中的安全主入口。已有明确事实继续保持：教学分流默认“从基础学起”；确认弹窗默认“取消”。
7. 鼠标与键盘/手柄状态可以共存；鼠标 hover 不清除 focus，输入方式切换不造成焦点丢失。

### 8.2 页面闭环顺序

下列是语义顺序，具体 NodePath 属于技术实现 `hypothesis`：

| 页面 | 必须形成的闭环 |
|---|---|
| 主菜单 | 按视觉阅读顺序遍历全部当前可用菜单项，末项回到首项 |
| 关卡选择 | 分类/章节 → 当前章节可见节点 → 关卡说明操作 → 进入/返回；切换分类后聚焦当前分类的首个可用节点 |
| 联机 | 输入/房间操作 → 席位状态动作 → 准备/开始/返回；状态显隐后跳过不可用项并保持闭环 |
| 正式对局 | 棋盘外围可聚焦入口 → 行动/模式操作 → 确认/取消 → 暂停/返回；确认面板打开时局部闭环且默认取消 |
| 教学 | 当前教学交互 → 继续/重试/下一章 → 暂停/返回；教学分流默认“从基础学起” |
| 设置 | 选项按从上到下顺序 → 页脚应用/取消/危险操作 → 回到首项；危险操作不是默认落点 |
| 加载失败 | 错误说明后的重试 → 返回，形成两项闭环 |
| 结算 | 继续/重试/下一章或再来一局 → 返回，形成当前可见动作闭环 |

## 9. 响应式布局标准

### 9.1 960×540 紧凑档

- 使用独立紧凑布局规则，不对 1280×720 UI 做全局等比缩小；
- 优先缩减外边距、装饰留白和次级同时显示数量；核心文字、按钮点击高度和焦点线不得降级；
- 允许次级内容进入 ScrollContainer 或折叠空状态，但核心行动、当前目标、失败原因和返回路径必须同时可达；
- 面板之间不得互相遮挡，滚动条不得压住正文，聚焦项必须自动滚入可见区域；
- 本档的正式性能组合为 `960×540 + reduced-motion`，仍需另做默认动态布局冒烟以发现几何溢出。

### 9.2 1280×720 基准档

- 作为核心 `16:9` 安全画布与全部页面的排版基准；
- 使用 Container、锚点和安全边距维护“左信息—中棋盘—右目标”等既定结构；
- 不以手工绝对坐标修补单一截图，不允许 hover/press 改变容器测量结果。

### 9.3 1920×1080 桌面档

- 保持核心功能区比例与阅读顺序，优先增加内容容器和棋盘可用空间；
- 不等比放大边框厚度，不让长行宽破坏正文阅读；
- 所有焦点边线、弹窗和提示必须保持在可见安全区内。

### 9.4 21:9 超宽档

- 以 `2560×1080` 作为自动与样片参考尺寸；
- 背景、雾气和无交互环境装饰延展至全宽，核心功能区保持居中的 `16:9` 安全画布；
- 棋盘、按钮、面板和焦点路径不得水平拉伸，左右新增区域不得出现仅一方可见的信息；
- 弹窗、Tooltip 与下拉列表按核心安全画布约束，不得因屏幕更宽移入无操作意义的边缘区域。

## 11. 技术交接与不合格回退

技术实现应继续复用：

- `scenes/game/ui/ui_motion_button.tscn`
- `scripts/game/presentation/ui/ui_motion_button.gd`
- `resources/game/ui/motion/terracotta_ui_motion_profile.tres`
- `resources/game/ui/themes/terracotta_ui_theme.tres`

现有 `PrimaryButton`、`SecondaryButton`、`DangerButton` 主题语义可作为迁移输入；`Confirm` 必须成为独立可测试的预置语义，即使其部分视觉资源与 Primary 复用。实现不得给基础 `Button` 写全局皮肤而污染非目标控件。

下列情况退回本任务规格循环，不进入正式页面批量迁移：

- 四类语义无法在现有动作中无歧义映射；
- 为实现视觉反馈必须读取隐藏状态或改变正式 Intent/Event 时序；
- 960×540 必须把核心文字缩到下限以下或把交互高度压到 44 px 以下；
- 显式焦点闭环与状态显隐发生不可解冲突；
- 实现需要改变规则语义、核心体验、正式二维方向或新增范围。

前四项提交差距、复现路径与备选方案给系统与体验负责人/技术负责人；最后一项必须升级项目经理与项目所有者，不得由实现岗位静默决定。
