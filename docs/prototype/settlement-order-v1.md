# 结算顺序 v1

状态：`prototype / iteration 1`。本表是 `rules-spec-v1.md` 的同窗顺序，不扩展规则语义。

## 行动事务

| 优先级 | 阶段 | 必须行为 |
|---:|---|---|
| 0 | 接收与校验 | 终局拒绝行动；校验行动方、普通/特殊互斥、区域/城墙/路径/终点/资源资格。非法请求不消费行动、弹药或随机数。 |
| 1 | 提交 | 锁定规范化行动；炮击先记录弹药消费，再按固定随机消费序号抽三个不同格；其他随机效果仅在对应事件实际触发时消费。 |
| 2 | 路径/位移 | 开始移动车时先移除其旧路径视野；执行位移。特殊车按路径顺序逐目标进入“单目标伤亡窗”。兵/卒穿越不产生伤亡。 |
| 3 | 单目标伤亡窗 | 将帅或士：直接实际死亡。其他棋子：若属于本方最先两次合资格阵亡事件，则尝试士替死；有可用士时随机移除一士并把目标随机部署到己方大本营空格，否则目标实际死亡。 |
| 4 | 最高优先终局 | 每个目标处理后立即检查将帅实际死亡；若发生，立即终局，不再处理车路径后续目标、墙、旗或轮上限。 |
| 5 | 临时状态 | 更新棋子位置、马隐身、相/象田字显形区、车新路径视野；清除因死亡/撤回/离位失效的位置状态。 |
| 6 | 城墙 | 分别计算两方缓冲区入侵数并触发倒塌；更新倒塌墙的恢复连续计时。满足完整轮条件时恢复并执行随机撤回。撤回中的伤亡规则不存在。 |
| 7 | 旗帜 | 对仍在旗格且符合条件的棋子累计“对方行动”进度；完成占领后检查是否同一方同时占三旗，若是终局。 |
| 8 | 完整轮上限 | 仅在双方行动构成完整轮的边界检查。达到配置值时比较旗数，同数平局。该配置值状态为 `unknown`。 |
| 9 | 投影与换手 | 生成分玩家可见事件/状态摘要，随后切换行动方；终局不换手。 |

追溯：`stmt:veilfront-xiangqi-siege:rook-rules`、`piece-rescue`、`general-capture-rules`、`wall-cycle`、`victory-and-flags`、`cannon-rules`。

## 特殊窗口

- **车路径**：目标按从起点到终点排序；对每个目标完整执行“阵亡候选→士替死/实际死亡→将帅死亡检查”，才可处理下一个目标。被替死目标已离开路径；将帅不合资格替死。
- **士替死**：左右士候选仅限仍存活且能力未消费者；随机选择及被救棋子目的地分别留下随机消费记录。复活不回滚既有资源消费。
- **城墙恢复**：只撤回恢复方大本营内入侵者；双方墙各自计算，不能用一方计时驱动另一方。
- **终局竞争**：已确认唯一硬优先级为“将帅实际死亡 > 其他胜负检查”；三旗在轮上限之前检查。

## `unknown` 冲突窗

炮击三个伤害格是顺序还是同时伤亡、双方将帅同窗死亡结果、多个随机撤回的分配顺序、空格不足、旗帜完整生命周期尚无 confirmed 语义。实现应把这些用例标成 `blocked_by_rule_decision`，不得用容器遍历顺序、阵营顺序或 RNG 顺序暗定胜负。
