# GATE-1 观测计划 v1

状态：`prototype / iteration 1`。本计划收集证据，不批准 GATE-1，不冻结回合上限、AI 预算、随机性或难度。

## 自动指标与硬检查

所有记录绑定 Contract/提交/构建、命令、环境、退出码、随机种子和证据路径。

| 类别 | 记录/判据 |
|---|---|
| 合法终止 | 至少 1000 个固定种子完整对局；崩溃、非法状态、无法终止结算、不可解释分歧均为 0。 |
| 确定性 | 同版本、初态、种子、行动序列的最终状态摘要与事件日志摘要完全一致。 |
| 规则矩阵 | 覆盖 24x9/区域边界、普通/特殊资格、双墙倒塌恢复、随机撤回、炮击、车逐目标、士替死、隐身/显形、三旗、将帅最高优先级、轮上限出口。 |
| 信息泄露 | 隐藏等价配对的合法意图、只读查询、错误外形、玩家事件、主棋盘/小地图输出一致；出现一项可区分即失败。 |
| AI 公平 | 等价 PlayerView、记忆和 AI 种子产生相同输入摘要与动作；FullState 访问次数必须为 0。 |
| 对局分布 | 按先后手记录胜率、胜因（三旗/将帅/轮上限）、完整轮长度分位数、旗数、墙倒塌/恢复、炮击、车多目标、替死触发次数。这里只报告，不设置平衡通过阈值。 |
| 随机审计 | 记录旗带/旗格、炮击三格、士选择、复活/撤回落点及消费序号；同种子可重放。分布仅提示偏差，不自动宣称平衡。 |

## 人工试玩问题

每局记录参与者、版本、种子、行动日志、结束原因和逐题 1..5 评分/文字证据：

1. 玩家能否不借助开发者解释说清当前行动目标、城墙状态、旗帜进度和胜负原因？
2. 移动—侦察—破城—炮击—争旗—吃将的选择是否形成连贯循环，还是存在长期无意义等待？
3. 迷雾与隐身造成的是可推理的不确定性，还是像界面故障/作弊？哪些反馈泄露过多或不足？
4. 墙倒塌、恢复撤回、士替死、车多目标与炮击的先后是否可理解？玩家能否复述关键结果原因？
5. 三旗与实际吃将是否都产生可行战略；是否出现单一路径压倒其他棋子价值？
6. 对局长度、思考负担、先手感受、随机挫败分别在何处达到峰值？
7. AI 是否显得公平、可解释且有挑战；怀疑作弊时对应的具体回合和可见证据是什么？

## 建议输出，不是批准结论

- 回合上限：用长度分位数、无进展轮数、轮上限胜因和人工疲劳点形成至少两个可逆候选；标记 `unknown / project-owner decision`。
- AI：按决策耗时、节点/候选数、胜率、动作多样性和人工公平感形成预算/随机性/难度候选；标记 `unknown / project-owner decision`。
- 平衡：只报告特殊行动使用率、收益、先后手差和异常种子，任何规则改动均作为变更请求返回规格循环。

## GATE-1 人工问题与边界

证据包应支持项目所有者判断：核心循环是否值得继续；胜负/恢复/视野/行动反馈是否闭环；最大风险是否真的被验证；技术成本与需重写范围是否可接受；是否进入正式功能开发及后续视觉准备。自动通过、QA 专业审查或本计划作者均不得代替该人工决定。
