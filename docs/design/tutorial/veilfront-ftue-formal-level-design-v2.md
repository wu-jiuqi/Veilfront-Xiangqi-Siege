# 《雾疆：九路烽棋》新手教学关卡正式设计 v2

状态：`draft / graybox-playtest / pending-project-owner-approval`

用途：本文件定义首版 Demo 的新手教学内容、固定局面、教学节奏、失败反馈与灰盒验收标准。它取代 v1 的五章摘要，但在项目所有者完成 HTML 灰盒试玩并明确批准前，不作为冻结生产基线。

## 1. 关卡定位

关卡名：**雾门初阵**。

一句话目标：用七个棋子训练局、两个特色机制局和一个综合考核，让第一次接触本作的玩家理解全部棋子及本作区别于传统象棋的核心规则，并能独立完成一次旗帜发现与占领。

目标玩家：

- 懂传统象棋基础，但不了解本作特殊规则的玩家；
- 不熟悉象棋，但能够理解交点移动与回合制战术的玩家；
- 首版 Demo 的本地教学玩家，不包含 AI 人机对战。

首通目标：25–35 分钟。每章 1–4 分钟，综合考核 6–10 分钟。章节可独立重试、跳过和复习。

## 2. 冻结设计原则

1. **先操作，后总结**：先让玩家完成一个可观察动作，再解释规则名称。
2. **每类棋子都亲手使用**：车、马、相/象、士、将/帅、炮、兵/卒均至少完成一次普通或特殊行动。
3. **特色机制必须可观察**：迷雾、旗帜记忆、城墙、缓冲区前置、相田阻挡、车路径视野、隐身马接触、炮击、公开阵亡记录和士献祭均需出现。
4. **不建立第二套规则**：未来 Godot 教学只提交正式 `NormalizedIntent`，只消费正式 `PlayerView`、`ActionPreview`、`VisibleEvent` 与 `VisibleError`。
5. **不因教学泄露隐藏信息**：提示不得读取隐藏旗位、隐身棋子或真实随机结果；固定局面的隐藏事实只存在于权威 Scenario。
6. **错误不惩罚时间**：教学要求之外的非法点击不消耗行动；给出公开原因后允许立即重试。
7. **灰盒先行**：本轮只验证学习顺序、提示强度、操作负担与信息边界，不冻结美术风格。

## 3. 总体结构

```text
操作校准
  ↓
兵 → 马 → 相 → 车 → 炮 → 士 → 将帅
  ↓
雾墙攻防 → 雾中旗帜
  ↓
综合考核
```

七个棋子训练局彼此独立。特色机制局组合此前学过的棋子。综合考核不再提供直接行动箭头，只保留目标、合法高亮和三级提示。

### 统一章节循环

```text
建立固定局面
→ 给出一个可执行目标
→ 玩家选择与预览
→ 玩家确认或取消
→ 正式规则结算
→ 根据公开结果判断教学条件
→ 总结规则
→ 写入章节检查点
```

## 4. 章节详细设计

权威坐标始终使用红方坐标：`X=1..9, Y=1..24`。红方视角令红营位于画面底部；黑方教学若未来启用，仅旋转显示，不改变坐标。

### T0 操作校准：棋落交点

**目标**：理解交点棋盘、选择、取消、右键标注与确认提交。

**固定局面**：红兵 `(5,4)`；其余区域只保留区域色块、城墙和教学指示，不部署敌子。

**玩家步骤**：

1. 左键选择红兵，观察交点高亮。
2. 在选中状态右键，必须只取消选择，不打开标注菜单。
3. 在未选中状态右键 `(4,5)`，依次预览圆、叉、方标记并放置圆形标记。
4. 重新选择红兵，选择 `(5,5)`，在确认栏中先查看行动摘要，再确认普通移动。

**错误反馈**：点击格子中心时将指示最近交点；选中状态首次右键只显示“已取消选择”；标注不会成为合法行动目标。

**通过条件**：记录一次取消、一次本地标注和一次已确认普通移动。

### T1 兵卒训练：穿阵不伤

**目标**：区分普通兵移动与特殊长距离穿越。

**固定局面**：红兵 `(5,10)`；黑卒 `(5,12)`、黑炮 `(5,13)`；目标 `(5,15)` 为空；红友军 `(4,13)` 用于负例。

**玩家步骤**：

1. 红兵从 `(5,10)` 普通前进到 `(5,11)`。
2. 选择特殊行动，从 `(5,11)` 沿纵线到 `(5,15)`，穿过两枚敌棋。
3. 结算后确认被穿过的敌棋仍存活，兵停在空终点，且没有形成路径视野。

**负例**：向后移动、移动超过五点、终点被占、穿过友军均显示公开拒绝；穿越不能当作吃子。

**通过条件**：完成一次普通移动和一次 2–5 点特殊穿越，并能在二选一问题中回答“穿越不伤害沿途敌棋”。

### T2 马训练：越腿入雾

**目标**：理解大本营内蹩马腿与特殊区域隐身马。

**固定局面 A**：红马 `(4,2)`，马腿 `(4,3)` 被红兵占据。

**固定局面 B**：红马 `(4,10)`，马腿 `(4,11)` 被占；敌墙完整；终点 `(5,12)` 位于特殊区域。黑象随后以脚本行动建立覆盖 `(5,12)` 的田字显形区。

**玩家步骤**：

1. 在局面 A 尝试 `(4,2)→(5,4)`，观察大本营内“蹩马腿”拒绝。
2. 切换局面 B，提交 `(4,10)→(5,12)`，观察特殊行动无视马腿并进入隐身。
3. 继续脚本行动，观察黑象田字区使马显形；显形原因消失后马可再次隐藏。

**通过条件**：完成一次特殊马移动，并正确判断“敌墙倒塌区域视野不等于反隐”。

### T3 相象训练：田字封路

**目标**：理解相的扩展视野及田字格对敌车、敌兵的阻挡。

**固定局面**：红相 `(3,10)`；象眼 `(4,11)` 被占；目标 `(5,12)`；敌车 `(8,11)`；敌卒 `(4,15)`；红车 `(2,10)`。

**玩家步骤**：

1. 提交红相 `(3,10)→(5,12)`，在特殊区域无视象眼。
2. 页面分别展示起点中心 `3×3`、路径田字九点、终点中心 `3×3` 的视野并集；只有田字九点使用黄色边框。
3. 预测敌车从 `(8,11)` 向 `(2,11)` 移动的首次接触点 `(5,11)`。
4. 预测敌卒从 `(4,15)` 向 `(4,10)` 特殊移动的首次接触点 `(4,12)`。
5. 观察己方红车沿 `Y=10` 从田字区正常通过。

**负例**：田字源只在缓冲区和战区有效；只阻挡敌方车与兵/卒；从田字内部向外离开不再次截停。

**通过条件**：两次停止点预测均正确。

### T4 车训练：蓝线开路

**目标**：理解车的多目标路径、路径视野与隐藏马接触。

**固定局面 A**：红车 `(2,9)`；黑卒 `(2,11)`、黑炮 `(2,13)`；目标 `(2,15)`；同线无友军。

**固定局面 B**：红车 `(6,9)`；未显形黑马 `(6,12)`；目标 `(6,15)`。

**玩家步骤**：

1. 在局面 A 选择 `(2,15)`，蓝色只描绘本次车路径。
2. 确认后按路径顺序处理两枚敌棋，停在 `(2,15)`；完整路径视野保留到该车下次移动开始。
3. 在局面 B 选择 `(6,15)`；结算时首次接触隐藏马，吃掉该马并停在 `(6,12)`。
4. 黑方脚本车吃掉一枚红兵，查看双方同步的公开阵亡记录，并只在红方视图看到持续一回合的己方阵亡虚影；红方不会看到被吃黑子的虚影。

**负例**：己方棋子不可穿越；隐藏马不得造成无反馈失败；相田首次交点优先形成公开停止结果。

**通过条件**：完成多目标车行动，并在提交前正确预测隐藏接触停止点。

### T5 炮训练：一架一轰

**目标**：区分传统炮吃子与区域轰炸。

**固定局面 A**：红炮 `(2,3)`；唯一炮架 `(2,5)`；黑车 `(2,7)`。

**固定局面 B**：另一红炮 `(8,3)`，弹药 2；黑墙完整；目标中心 `(5,12)` 的完整 `3×3` 位于特殊区域；其中包含一枚红友军以展示友伤风险。

**玩家步骤**：

1. 使用普通炮隔恰好一枚炮架吃掉 `(2,7)` 的黑车。
2. 使用仍在己方大本营的另一门炮选择 `(5,12)` 为轰炸中心。
3. 确认面板只显示中心、九点风险区、弹药和可能友伤，不预告三个随机命中点。
4. 确认后由固定种子抽取三个不同伤害点，弹药减一；说明不存在共享冷却。

**负例**：炮离开己方大本营、敌墙非完整、弹药为零或中心 `3×3` 越界时不可提交。

**通过条件**：完成一次精确吃子和一次区域轰炸，并正确回答“同一门炮剩余弹药允许时不需要等待冷却”。

### T6 士训练：以身换援

**目标**：理解九宫移动、公开阵亡记录、复活候选池和可取消献祭。

**固定局面**：红士 `(4,1)`；红方公开阵亡记录包含红车、红兵、红士、红帅；红方大本营至少两个空点。

**玩家步骤**：

1. 红士在九宫内斜走到 `(5,2)`。
2. 打开“献祭复活”，查看候选统计与风险说明，然后选择取消；取消不得消费行动。界面必须停留并明确显示“士仍在场、行动未消耗”，不得自动伪装成再次待确认。
3. 玩家主动选择“继续学习献祭”后，再次打开并确认。士先进入公开阵亡记录，再从红车、红兵中随机选择一个复活到红营空点。
4. 页面明确标注阵亡士和帅虽然存在于公开阵亡记录，但不属于复活随机池。

**负例**：没有合资格候选，或献祭后仍无大本营空点时，行动不可提交。

**通过条件**：先取消一次，再确认一次合法献祭；能够指出公开阵亡记录不等于复活候选池。

### T7 将帅训练：实际阵亡

**目标**：理解本作取消将军、应将、照面和飞将，只以实际死亡结算。

**固定局面 A**：红帅 `(5,1)`，九宫内可移动点 `(5,2)` 位于敌方攻击范围。

**固定局面 B**：红车已合法位于黑方大本营 `(5,22)`；黑将 `(5,24)`；路径 `(5,23)` 为空。

**玩家步骤**：

1. 将红帅移至 `(5,2)`，确认进入攻击范围本身不会触发失败。
2. 在局面 B 使用红车实际吃掉黑将。
3. 观察黑将先进入公开阵亡记录，随后以同一结算窗口最高优先级结束对局。

**通过条件**：完成一次将帅九宫移动和一次实际击杀，并回答“只有实际被吃掉才失败”。

### T8 特色机制：雾墙攻防

**目标**：掌握完整城墙、三子破墙、倒塌视野和缓冲区进攻前置。

**固定局面**：两枚红子已位于黑方缓冲区；第三枚红车位于战区 `(7,16)`；另一红车位于 `(2,16)`；黑墙完整；黑营目标 `(2,23)`。

**玩家步骤**：

1. 第三枚红子进入黑方缓冲区 `(7,18)`，使入侵者达到三枚并触发黑墙 `BREACHED`。
2. 观察黑缓冲区和黑营的迷雾被区域视野穿透，但隐藏马仍不自动显形。
3. 尝试让 `(2,16)` 的红车直接攻击 `(2,23)`，收到“必须先进入守方缓冲区”的公开拒绝，行动不消耗。
4. 先移动到 `(2,20)`，下一次行动再进入或攻击 `(2,23)`。

**通过条件**：完成破墙，并遵循“战区→缓冲区→大本营”的两次行动顺序。

### T9 特色机制：雾中旗帜

**目标**：理解旗帜发现记忆、公开占领进度和位置保密。

**固定局面**：三旗仍由固定教学种子布置在战区；本章目标旗位于 `(6,13)`，初始不在红方视野；红相 `(3,10)`；红兵可在后续抵达 `(6,13)`。

**玩家步骤**：

1. 红相移动到 `(5,12)`，其终点视野首次覆盖 `(6,13)`，显示旗帜。
2. 相离开后该点重新入雾，但红方地图保留旗帜记忆图标；黑方未发现时仍不得获得坐标。
3. 红兵停在旗点，开始 `红方正在夺旗(1/3)`。
4. 两次脚本化黑方行动后进度依次成为 `2/3`、`3/3`，显示成功消息。
5. 展示一个非提交分支：占领者离开或死亡会清零；敌方重占期间原所有权保留但 `contested=true`。

**通过条件**：发现并夺得一面旗，能解释“公开夺旗进度不等于公开旗位”。

### T10 综合考核：第一面战旗

**目标**：不依赖直接箭头，组合运用已学机制。

**固定局面**：每方 5–7 枚棋子；红方至少拥有兵、马、相、车、炮、士和帅中的可用代表；一面目标旗未发现；存在一枚隐藏马、一个可建立的相田阻挡和一个可选献祭恢复机会。敌方只执行固定、可重放的合法脚本。

**必做任务**：

1. 建立视野并发现目标旗；
2. 正确处理一次相田阻挡或隐藏马路径接触；
3. 让指定棋子抵达旗点并维持到 `3/3`；
4. 在八个己方行动内夺旗。

**可选任务**：不使用三级演示；保留至少一发炮弹；不献祭士。

**失败与恢复**：占领者死亡、八次行动用尽或帅实际死亡时，本章失败；只重置 T10，不清除前九章完成记录。

**通过条件**：夺得目标旗。结算页按“侦察、路径判断、资源使用、无效操作”四项回顾，不使用分数评价玩家人格或能力。

## 5. 提示与失败系统

每个教学目标独立统计无效尝试：

| 次数 | 反馈 |
|---:|---|
| 第 1 次 | 显示违反的公开规则和一个短句原因，不消耗行动 |
| 第 2 次 | 高亮相关起点、路径、城墙、田字九点或候选池 |
| 第 3 次 | 提供“查看演示”按钮；演示只播放输入顺序，不替玩家提交 |
| 第 4 次及以后 | 保持三级提示，并提供“重置本步骤” |

对于随机炮击、随机复活、隐藏马和隐藏旗，错误反馈不得暴露未进入 PlayerView 的具体结果。

## 6. HTML 灰盒验证范围

HTML 是脚本化教学体验模拟器，用于验证：

- 章节顺序和信息密度；
- 交点选择、右键取消与标注；
- 行动预览、确认、取消和公开错误；
- 迷雾、旗帜记忆、蓝色车路径、黄色相田九点；
- 章节检查点、提示升级和综合考核节奏；
- 960×540、1280×720、1920×1080 的基本适配。

HTML 不承担：

- 完整规则合法性；
- 权威随机与回放；
- PlayerView 信息安全证明；
- Godot 场景、资源、动画或美术验收；
- AI 对手行为。

页面中所有未实现的规则均明确显示为“脚本演示”，避免把灰盒原型误认为生产事实源。

## 7. 后续 Godot 生产边界

HTML 经项目所有者试玩批准后，才允许把本设计冻结为 Godot 教学输入。正式实现应使用：

- 预置 `TutorialScenarioDefinition` Resource 保存固定种子、绑定席位、允许的教学目标和检查点；
- 预置教学关卡、Overlay、确认面板和章节导航节点；
- `TutorialDirector` 仅负责教学状态，不读取 `FullState`；
- `ApplicationHost` 负责权限、预览、提交、重试、跳过和脚本对手行动；
- `Projection` 仍是玩家视图唯一出口；
- 所有正式行动和敌方脚本都经过同一规则核心。

每章必须具备正向流程、公开拒绝、重置一致性、隐藏等价和三档布局测试。未经项目所有者批准，不启动美术替换。

## 8. 灰盒验收问题

项目所有者试玩 HTML 时重点回答：

1. 是否能在没有额外口头说明的情况下理解每章目标？
2. 七类棋子的普通规则与特色规则是否区分清楚？
3. 相、车、马三个复杂机制的教学顺序是否合理？
4. 士献祭“先取消、再确认”的流程是否自然？
5. 破墙后仍需先进入缓冲区的规则是否容易记住？
6. 旗帜记忆与公开夺旗消息是否会被误解为全图公开旗位？
7. 25–35 分钟是否过长，哪些章节应允许快速跳过？
8. 综合考核是否足以证明玩家能够独立完成一次夺旗？

只有上述问题没有阻断性异议后，才提交本设计与 HTML，并进入 Godot 教学逻辑实施计划。
